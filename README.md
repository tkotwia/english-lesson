# 英文課

在自己電腦上執行的英文學習網站。由 AI 老師 Emma 帶著上課,每堂 20–40 分鐘,涵蓋聽、說、讀、寫。課後自動評分,記下不會與不熟的地方,並依 CEFR 等級(A1–C2)安排難度。

所有進度都存在這台電腦上。AI 使用 Google Gemini API 的免費額度。

## 需要準備

- macOS,已安裝 [Node.js](https://nodejs.org) 24 以上。
- 桌面版 Google Chrome。口說與聽力用的是 Chrome 內建的語音功能。
- 每位使用者一把 Google API key(見下方)。

## 第一次設定

1. 在 Finder 對 `start.command` 點兩下。第一次會自動安裝套件,接著用 Chrome 開啟網站。
2. 按「新增使用者」,輸入名稱、學習階段(國小、國中、高中、大學)與 CEFR 等級。
3. 到「設定」頁貼上 Google API key,按「測試連線」確認可用。

### 取得 Google API key

1. 用**成年人**的 Google 帳號登入 [Google AI Studio](https://aistudio.google.com/apikey)。
2. 建立 API key,複製後貼到網站的「設定」頁。
3. 不要開啟付費。沒有開啟付費時,額度用完只會被拒絕,不會扣款。

免費額度以 Google 專案計算。多位使用者的 key 若來自同一個專案,額度是共用的;要各自獨立,每把 key 必須來自不同的專案。

## 每天怎麼用

1. 點兩下 `start.command`,選擇使用者。
2. 按「開始上課」,選 20、30 或 40 分鐘。
3. 上完課看分數與老師的評語。
4. 要停止程式,關掉 `start.command` 開出來的終端機視窗。

右上角隨時可以切換使用者。切換不需要密碼,所以這台電腦上的任何人都能進入任何使用者。

## 做成 App(不用開終端機)

在終端機進到專案資料夾,執行一次:

```bash
./scripts/make-app.sh
```

資料夾裡會多一個「英文課.app」。之後點它就會啟動程式並開啟 Chrome,不會出現終端機視窗。

- **停止**:結束這個 App(Cmd+Q,或在 Dock 的圖示上按右鍵選「結束」)。App 開著就是程式在執行,App 關掉程式就停止。
- **已經開著時再點一次**:只會把網頁再開出來,不會重複啟動。
- **第一次啟動**要安裝套件,約一兩分鐘,期間會跳出一個說明視窗。
- **啟動紀錄**在 `~/Library/Logs/english-lesson.log`。原本顯示在終端機的訊息(例如每次呼叫 AI 花了幾秒)都寫在這裡;啟動失敗時 App 也會顯示最後幾行。
- App 裡記著專案資料夾的位置。**搬動專案資料夾之後要重新執行一次** `./scripts/make-app.sh`。
- 專案資料夾如果放在「文件」「桌面」或「下載項目」裡,macOS 第一次會詢問是否允許這個 App 取用該資料夾,請按允許。
- App 用的是系統預設的圖示。`start.command` 仍然可以照常使用。

## 讓這台 Mac 的所有帳號都能用

用管理員帳號做一次:

1. 用 [nodejs.org](https://nodejs.org) 的 macOS 安裝檔(.pkg)安裝 Node.js,這樣每個帳號都找得到。用 nvm 這類工具裝的只有安裝的帳號能用。
2. 把專案放到共用資料夾,並開放所有帳號讀寫(之後新產生的檔案也自動適用):
   ```bash
   mv english-lesson /Users/Shared/english-lesson
   cd /Users/Shared/english-lesson
   chmod -R +a "group:staff allow read,write,execute,append,delete,delete_child,readattr,writeattr,readextattr,writeextattr,readsecurity,file_inherit,directory_inherit" .
   ```
3. 把 App 產生在「應用程式」裡,每個帳號的 Launchpad 都會看到:
   ```bash
   ./scripts/make-app.sh /Applications
   ```

這樣所有帳號共用同一份資料:網站裡的使用者清單、進度與 API key 是同一份。訪客帳號不屬於 `staff` 群組,不適用。

前一個帳號沒關掉 App 就切換使用者時,下一個帳號點 App 會直接接上已經在執行的那一份;前一個帳號登出後程式會停止,再點一次 App 即可。

## 一堂課的內容

| 階段 | 內容 | 配分 |
|---|---|---|
| 暖身複習 | 之前不會或不熟、今天到期的項目 | 10 |
| 聽力 | 不看文字聽課文,回答問題,再做聽寫 | 15 |
| 閱讀 | 讀課文,回答細節與推論題 | 15 |
| 單字與文法 | 當課單字與一個文法重點的練習 | 20 |
| 口說 | 跟讀句子,再與老師做情境對話 | 20 |
| 寫作 | 短篇寫作,由 AI 批改 | 20 |

課堂中可以按右下角的「問老師」提問,每堂最多 5 次,不計分。

### 評分規則

- 每題有兩次機會。第一次就對得滿分;第二次才對,或看了提示才對,得半分並列入**不熟**;兩次都錯得零分並列入**不會**。
- 聽寫與跟讀看單字正確率:90% 以上算對,70–90% 算不熟,低於 70% 算不會。
- 對話與寫作由 AI 依該等級的期望打 0–100 分。
- 任何單字或題目都可以按「我不熟」,手動加入複習。
- 無法進行的部分不計分,其餘配分等比例放大,滿分仍是 100:
  - 第一天沒有複習項目,就沒有暖身複習。
  - 瀏覽器不能朗讀,就沒有聽力。
  - 麥克風不能用,口說只算對話(改用打字)。
  - AI 對話服務無法使用而跳過對話時,口說只算跟讀。

## 日曆與升級

- 「日曆」頁顯示每天的分數。當日分數是當天所有課程的平均;月平均是有上課日的當日分數平均。
- 一個月結束後,如果上個月的月平均達 **95 分**,首頁與日曆會建議升到下一個 CEFR 等級。可以選「升級」或「先不要」。
- 只計入在目前等級上的課,而且不限上課天數。一個月只上一堂課並拿到 95 分,也會出現建議。
- 等級也可以隨時在「設定」頁手動調整。
- 重上的課不計入當日分數、月平均與升級判定(見下一節)。

## 重上一堂課

每堂課的課文、題目與作答都存在資料庫裡。分數不理想時,可以在那堂課的結果頁按「重上這堂課」,用同一份內容再上一次。

- 重上**只當練習**:題目已經看過,第二次一定比較高分,所以分數不計入日曆與月平均。日曆上會在原本那堂課底下註明重上了幾次、各得幾分。
- 不會與不熟的項目照常更新。同一題再錯一次,是累加在同一個項目上。
- 重上不需要 AI 重新備課,不耗產生課程的額度;只有對話與批改會用到。
- 還有課沒上完時不能重上,要先上完或放棄那堂課。

## 課程會不會重覆

會盡量避免,而且由程式檢查,不是只相信 AI:

- **主題**:每個學習階段有 20 個主題,程式挑最久沒上過的。整份清單輪完之前不會重覆;輪完之後主題會再出現,這時程式會把以前同主題的課名告訴 AI,要求寫不同的情境。
- **文法重點**:由程式依清單順序(由淺到深)指定,AI 不能自己挑。每個等級有 6–11 個,輪完一遍才回到第一個。
- **單字**:最近 60 堂課的重點單字會告訴 AI 避開。學生還不熟的單字則會刻意放回新課文裡再接觸一次,但不佔新單字的名額。
- **檢查**:課程產生後,程式把新課文和所有上過的課文比對,算出相似度(兩篇課文中連續三個字的片段有多少比例相同)。同主題但重寫過的課文通常低於 10%;達 50% 就視為幾乎相同,會要求 AI 重新產生一次(那堂課多用 1 次品質類額度,只重試一次)。
- 比對結果記在每堂課裡,結果頁最下方的「重覆檢查」可以看到:比對了幾堂、最像哪一堂、相似度多少、哪些重點單字以前教過。
- 每個等級的第一堂 20 分鐘課是內建的起始課(見「備課要等多久」),內容固定,所以沒有重覆檢查的結果。它教過的主題、文法與單字同樣會算進上面的規則;已經備好、還沒上的課也算。

## 回顧與複習

- 「回顧」頁可以看本週、本月或指定月份不會與不熟的內容,並直接練習。
- 不會與不熟的項目依 1 → 2 → 4 → 8 → 16 天的間隔再次出現。答對就拉長間隔,答錯回到 1 天;間隔達 16 天仍答對,標為已掌握。
- 還沒到期就提前練習而答對的,不會拉長間隔。
- 複習全部在本機判分,不耗 AI 額度。

## 資料與備份

所有資料存在 `data/english.db` 這一個檔案裡,包含使用者、上課紀錄、複習項目與每個人的 API key。

- **備份**:先停止程式,再複製整個 `data` 資料夾。
- **佔用空間**:一堂課連同作答、結果與弱點項目約 40 KB。每天一堂、上一整年約 13 MB。
- 程式更新後第一次啟動時,會自動替舊資料庫補上新欄位,原有的紀錄不會變動。
- **搬到另一台電腦**:把 `data` 資料夾放到新電腦上專案的同一個位置。
- API key 以明碼存在這個檔案裡。把檔案給別人,等於把 key 也給了對方。

## 免費額度與模型

程式把 AI 呼叫分成兩類,用不同模型,以節省額度:

| 類別 | 用途 | 每堂次數 | 預設模型 |
|---|---|---|---|
| 品質類 | 產生整堂課、批改對話與寫作 | 2(課文和舊課幾乎相同而重新產生時 3) | `gemini-4-hydrogen` → `gemini-3.8-flash` → `gemini-3.5-flash-lite` |
| 對話類 | 情境對話、問老師 | 最多 13 | `gemini-3.5-flash-lite` |

前面的模型額度用完或不可用時,自動改用後面的。全部用完時,畫面會說明並引導去做複習。

上表是每上一堂課的用量。另外,第一次在某個等級開課時,程式會在背景先備好三種長度的課,也就是多用 3 次品質類額度;之後每用掉一堂才補一堂(見下方「備課要等多久」)。

Google 不公布各模型的免費額度,實際數字要到自己的 AI Studio 查看。每日額度在台灣時間下午 3–4 點重置。「設定」頁會顯示本次額度週期已經呼叫幾次、用了多少 token。

要更換模型,把 `.env.example` 複製成 `.env`,修改 `AI_MODELS_QUALITY` 與 `AI_MODELS_CHAT`。

### 備課要等多久

AI 產生一堂課需要時間,實測現場產生約 40–80 秒。為了不讓學生等,程式做了兩件事。

**內建的起始課。** 程式裡附了 24 堂寫好的 20 分鐘課:6 個等級(A1–C2)× 4 個學習階段各一堂。使用者在某個「等級 + 學習階段」還沒上過課時,選 20 分鐘就直接上這一堂,不呼叫 AI、不用等、不耗產生課程的額度。所以切到新的等級(包含接受升級建議)之後,第一堂課可以馬上開始。

- 起始課是事先寫好的,不是 AI 當場產生的,每位使用者看到的內容相同。
- 它只用在該等級的第一堂。之後的課由 AI 產生,並會避開起始課的主題、文法重點與單字。
- 30 與 40 分鐘沒有起始課。
- 對話與批改仍然需要 API key,所以沒有設定 key 的使用者一樣不能開課。

**預先備課。** 一堂課開始之後,程式在背景把這個等級的 20、30、40 分鐘各準備一堂並存起來,先準備學生這次選的長度。

- 開始上課的畫面會標示每種長度的狀況:「已備好」可以馬上開始,「準備中」表示背景正在準備。
- 用掉一堂就補一堂。備好的課存在資料庫裡,關掉程式再開也還在。
- 備好的課是照「等級 + 學習階段 + 長度」分開存的。切到別的等級再切回來,原本備好的課還在,可以直接用。
- 同一位使用者一次只產生一堂課。背景正在準備時按「開始」,學生要的那一堂會排在正在做的那一堂後面、優先於背景剩下的工作。

以下情況仍然需要等:

- 在新的等級,第一堂就選 30 或 40 分鐘。
- 背景還沒備好就按「開始」。
- 背景備課失敗(例如額度用完、模型忙線)。這時背景會先停下來,不會繼續嘗試其他長度;下次開課或上完課時再試。

需要等的時候,畫面會顯示**進度條、百分比與預估剩餘時間**(批改時也是)。AI 是一次回傳整個結果,過程中拿不到真正的進度,所以這些數字是用「過去實際花費的時間」推估的:還沒有紀錄時以 60 秒估計,之後每次實際花的時間都會納入。等得比預估久時,進度條會慢下來但不會顯示 100%,並改為顯示已經等了多久。

**額度。** 預先備課會提前使用額度:第一次在某個等級開課時,背景會連續產生 3 堂課(三種長度各一堂),之後每用掉一堂補一堂。免費額度很緊的話,可以在 `.env` 調整:

- `AI_PREPARE_MINUTES=20`:背景只備 20 分鐘的課(可以填多個,例如 `20,30`)。其他長度要用時才現場產生。
- `AI_PREPARE_NEXT=off`:完全不在背景備課,每次按「開始」才現場產生。內建的起始課仍然會使用。

#### 時間花在哪裡

2026-11-20 用真實的 key 產生 B2、20 分鐘課程的實測:

| 模型與思考程度 | 時間 | 品質 |
|---|---|---|
| `gemini-4-hydrogen`,模型預設(第一順位) | 40 秒、61 秒,另一次回「需求過高」 | 好,但速度看當下負載 |
| `gemini-3.8-flash`,模型預設(第二順位) | 79 秒 | 好;思考用掉的 token 是輸出的三倍 |
| `gemini-3.8-flash`,思考程度 low | 24 秒、33 秒 | 題目與答案正確,但對指示(例如課文字數)遵循得較不精確 |
| `gemini-3.5-flash-lite` | 8 秒 | 題目會出錯,只當最後備援 |

時間幾乎都花在模型的「思考」上。思考程度維持模型預設(品質優先),等待的問題交給預先備課解決。想改用較快的設定,可以在 `.env` 設 `AI_THINKING_QUALITY=low`。

另外,為了在模型出狀況時不白等:

- 每次呼叫都有逾時(品質類 180 秒、對話類 30 秒),超過就換下一個模型。SDK 預設是沒有逾時的。
- 關掉 SDK 自己的重試。模型忙線時立刻換備援,而不是在同一個模型上重試好幾次。
- 記住剛失敗的模型:額度用完的,到下一個額度日之前不再嘗試;忙線或逾時的,先跳過 5 分鐘。

「設定」頁的用量表會顯示每個模型平均每次等多久;啟動程式的終端機視窗裡,每次呼叫也會印出一行,例如 `[ai] lesson gemini-4-hydrogen 40.0 秒`。

## 隱私與 Google 條款

- **Gemini API 的條款規定使用者須年滿 18 歲,且不得用在可能被未滿 18 歲者使用的應用程式。** 讓未成年學生使用不符合這項條款,可能的後果是 key 被停用。是否這樣使用,由建立 key 的成年人自行判斷。
- 使用免費額度時,送出的內容會被 Google 用來改進產品,也可能由人工審閱。
- 程式送給 Google 的只有等級、學習階段、課程內容與學生的作答,不包含使用者的名稱。
- 請提醒學生,作答時不要寫出真實姓名、地址、學校、電話等個人資料。
- 語音辨識是 Chrome 的功能,說話的聲音會送到 Google 的語音服務處理。

## 已知限制

- 跟讀的分數代表「能不能被聽懂」,不是精確的發音評分。Chrome 會盡量猜出說的字。數字可能被辨識成阿拉伯數字而拉低正確率。
- 對話是一人說完換另一人,不是即時語音。
- 課文中只有加了底線的字可以點開看意思,不是每個字都能查。其他的字可以用「問老師」。
- 沒有入學分級測驗,也不會建議降級;起始等級與降級都靠手動調整。
- 重覆檢查比對的是課文的字面相似度。情節相似但用字完全不同的兩篇課文,不會被判為重覆。
- 每個學習階段的主題只有 20 個,每天上課的話大約三週輪完一遍。
- 內建的起始課每位使用者都一樣,而且沒有經過 AI 依個人弱點調整。等待時的進度條是推估值,不是實際進度。
- 只支援桌面版 Chrome,手機與平板無法使用。伺服器只接受這台電腦自己的連線。

```bash
node scripts/compare-models.ts <使用者編號>
```

用該使用者的 key,讓每個設定的模型各產生 A1 與 B2 的課程,回報是否通過格式驗證與 token 用量,並把課程存到 `data/model-comparison/` 供人工檢查。這會消耗真實的免費額度。

### 程式結構

```
shared/     前後端共用:資料結構、判分、間隔重複、升級規則(純函式,有測試)
server/     本機伺服器:資料庫、API、給 AI 的提示
  ai/       AI 層:provider.ts 是介面,gemini.ts 與 mock.ts 是兩個實作
  starters/ 內建的 24 堂起始課(每個等級一個檔案);starters.test.ts 檢查內容是否符合課程規則
client/     網頁
scripts/    示範資料與模型比較
```

### 改接其他 AI 供應商或本機模型

課程程式只呼叫 `server/ai/provider.ts` 定義的介面。新增一個實作檔,在 `server/ai/index.ts` 註冊,再把 `.env` 的 `AI_PROVIDER` 改成它的名稱即可。提示文字在 `server/ai/prompts.ts`,與供應商無關。
