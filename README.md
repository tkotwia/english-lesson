# 英文課

在自己電腦上執行的英文學習網站。由 AI 老師 Emma 帶著上課,每堂 20–30 分鐘(依學習階段固定),涵蓋聽、說、讀、寫。課後自動評分,記下不會與不熟的地方,並依 CEFR 等級(A1–C2)安排難度。

所有進度都存在這台電腦上。AI 使用 Google Gemini API 的免費額度。

## 第一次設定

需要 macOS、桌面版 Google Chrome(口說與聽力用的是 Chrome 內建的語音功能),以及 [Node.js](https://nodejs.org) 24 以上(用官網的 macOS 安裝檔安裝)。

1. 打開「終端機」,下載程式並產生 App:
   ```bash
   git clone https://github.com/tkotwia/english-lesson.git
   cd english-lesson
   ./scripts/make-app.sh
   ```
2. 資料夾裡會多一個「英文課.app」,點兩下打開它。第一次要安裝套件,約一兩分鐘,好了會自動開啟 Chrome。
3. 在網頁上按「新增使用者」,輸入名稱、學習階段與 CEFR 等級。
4. 到「設定」頁貼上 Google API key,按「儲存」,再按「測試連線」。

之後就不需要終端機了。App 可以拖到 Dock 上。第一次使用 `git` 時,macOS 可能會要求安裝開發者工具,按「安裝」即可。

### 取得 Google API key

1. 用**成年人**的 Google 帳號登入 [Google AI Studio](https://aistudio.google.com/apikey)。
2. 建立 API key,複製後貼到網站的「設定」頁。
3. 不要開啟付費。沒有開啟付費時,額度用完只會被拒絕,不會扣款。

每位使用者各貼一把 key。免費額度以 Google 專案計算:多把 key 若來自同一個專案,額度是共用的;要各自獨立,每把 key 必須來自不同的專案。

### 讓這台 Mac 的所有帳號都能用

用管理員帳號,把上面第 1 步換成下面這樣(其餘相同):

```bash
cd /Users/Shared
git clone https://github.com/tkotwia/english-lesson.git
cd english-lesson
chmod -R +a "group:staff allow read,write,execute,append,delete,delete_child,readattr,writeattr,readextattr,writeextattr,readsecurity,file_inherit,directory_inherit" .
./scripts/make-app.sh /Applications
```

App 會出現在每個帳號的「應用程式」裡。所有帳號共用同一份資料:網站裡的使用者清單、進度與 API key 是同一份。訪客帳號不適用。

前一個帳號沒結束 App 就切換到另一個帳號時,另一個帳號點 App 會直接接上已經在執行的那一份。前一個帳號登出後程式會停止,再點一次 App 即可。

## 更新程式

GitHub 上有新版本時:

1. 結束「英文課」App(Cmd+Q)。
2. 在終端機進到專案資料夾,執行:
   ```bash
   git pull
   npm install
   ```
3. 再打開 App。

不用重新產生 App,也不用另外建置:每次啟動都會自動重新建置網頁,舊資料庫也會自動升級,原有的紀錄不會變動。

所有帳號共用的安裝,請用當初安裝的那個帳號更新;其他帳號執行 `git pull` 會被 git 拒絕。

## 每天怎麼用

1. 打開「英文課」App,選擇使用者。
2. 按「開始上課」,再按「開始」。課程長度依學習階段固定,不用選:國小 20 分鐘、國中 25 分鐘、高中與大學 30 分鐘。如果畫面上是「備課」按鈕,表示下一堂課還沒備好:按下去等大約一分鐘,備好了再按「開始」(見「備課要等多久」)。
3. 上完課看分數與老師的評語。
4. 要停止程式,結束這個 App(Cmd+Q,或在 Dock 的圖示上按右鍵選「結束」)。

右上角隨時可以切換使用者。切換不需要密碼,所以這台電腦上的任何人都能進入任何使用者。

- App 開著就是程式在執行。不小心關掉網頁時,再點一次 App 就會把網頁開回來。
- 啟動失敗時,App 會顯示原因。完整的啟動紀錄在 `~/Library/Logs/english-lesson.log`。
- 搬動專案資料夾之後,要重新執行一次 `./scripts/make-app.sh`,因為 App 裡記著資料夾的位置。
- 專案資料夾如果放在「文件」「桌面」或「下載項目」裡,macOS 第一次會詢問是否允許 App 取用該資料夾,請按允許。

## 一堂課的內容

| 階段 | 內容 | 配分 |
|---|---|---|
| 暖身複習 | 今天到期的複習項目:學過的新單字,以及之前不會或不熟的內容 | 10 |
| 聽力 | 不看文字聽課文,回答問題,再做聽寫 | 15 |
| 閱讀 | 讀課文,回答細節與推論題 | 15 |
| 單字與文法 | 當課單字與一個文法重點的練習 | 20 |
| 口說 | 跟讀句子,再用即時語音與老師做情境對話 | 20 |
| 寫作 | 短篇寫作,由 AI 批改 | 20 |

課堂中可以按右下角的「問老師」提問,每堂最多 5 次,不計分。

老師的中文輔助隨等級遞減:A1–A2 用中文講解,B1 中英並用,B2 以上全英文。

- **課前重溫上一課**(第二堂課起,不計分,可以跳過):用上一課已經熟悉的課文練「快」。不看文字再聽一次、計時重讀(會顯示每分鐘讀幾個字,並和上次比較)、一分鐘重述(用說的,沒有麥克風就用打的,會顯示說了幾個字)。不呼叫 AI,不耗額度。
- **聽力課文與聽寫句子用事先唸好的自然語音播放**,不是電腦的朗讀語音(見「聽力音檔」)。還沒做好或當天額度用完時,那一段改由 Chrome 朗讀。
- 練習單字時,單字表會先收起來,要靠自己回想;做完單字練習後會再顯示。
- 跟讀的錄音不會因為停頓而結束,唸完要按「唸完了」;超過 30 秒沒有聽到新的內容,才會自動結束。
- **情境對話用即時語音進行**:按「開始對話」後不用再按任何按鈕,直接說,停下來約 1.2 秒老師就用聲音接話(見「即時語音對話」)。也可以按「改用打字對話」,用原本一來一往的方式。

### 評分規則

- 每題有兩次機會。第一次就對得滿分;第二次才對,或看了提示才對,得半分並列入**不熟**;兩次都錯得零分並列入**不會**。
- 聽寫與跟讀看單字正確率:90% 以上算對,70–90% 算不熟,低於 70% 算不會。
- 對話與寫作由 AI 依該等級的期望打 0–100 分。
- 兩次都答錯時會顯示正確答案,並用黃底標出答錯的地方:克漏字是該填的字,重組、聽寫與跟讀是沒有對上的字。
- 當課的單字、課文裡有底線的字,以及答對的聽力、閱讀與文法題,都可以按「我不熟」手動加入複習(答錯的本來就會進入複習)。
- **訂正練習**(課後,不計分):老師在寫作與對話裡指出的錯誤,要看著原本的句子把正確的說法打出來;正確的說法在訂正之後(或選擇略過)才顯示。照抄原句不算過關。老師的訂正以整句為單位:一句話裡有幾個錯,會一起改在同一句裡。
- 無法進行的部分不計分,其餘配分等比例放大,滿分仍是 100:
  - 第一天沒有複習項目,就沒有暖身複習。
  - 瀏覽器不能朗讀,就沒有聽力。
  - 麥克風不能用,口說只算對話(改用打字)。
  - AI 對話服務無法使用而跳過對話時,口說只算跟讀。

## 日曆與等級

- 「日曆」頁顯示每天的分數。當日分數是當天所有課程的平均;月平均是有上課日的當日分數平均。
- 重上的課不計入當日分數與月平均(見「重上一堂課」)。
- 等級不會自動改變。要知道適不適合現在的等級,做「分級測驗」;也可以隨時在「設定」頁手動調整。

### 分級測驗

隨時可以從上方的「分級測驗」開始。

- 從 A1 到 C2,每個等級 8 題:單字 2 題、文法 3 題、閱讀 2 題、聽力 1 題,全部是選擇題,每題只作答一次。瀏覽器不能朗讀時沒有聽力題,每級是 7 題、要答對 6 題。
- 由低到高作答。一個等級答對四分之三以上(8 題對 6 題)才進下一級;**第一個沒通過的等級,就是建議上課的等級**。後面的等級不再作答,所以程度越高題數越多,大約 5–15 分鐘。
- 做完後顯示每一級的答對題數與建議的等級。要不要切換由你決定;建議可能比現在高,也可能比較低。頁面下方列出最近 10 次的測驗結果。
- 做到一半離開的話,下次是同一份題目,從第一題重新開始。
- 作答與判分都在本機進行,不耗 AI 額度,也不列入日曆分數。
- **題目是預先備好的**:第一次用程式內建的一份題目,不必等。一開始作答,程式就在背景請 AI 出下一份(用掉 1 次品質類額度)並存起來,下次再測也不必等。背景出題失敗時,下次按開始才現場出題,畫面會顯示進度條。沒有設定 API key 的話,只能重複做內建的那一份。
- **AI 出的題目要通過程式的檢查才會採用**:六個等級齊全、題數與選項數正確、短文與聽力內容夠長。選項的順序由程式打亂,正確答案不會集中在某個位置。
- **老師出不了合格的題目時**(模型忙線、額度用完,或出的題目沒通過檢查),會改用之前做過的內建題目,並在作答畫面說明原因。題目看過了,這種情況下的結果可能比實際程度高。
- 這是粗略的分級,不是正式檢定:每一級只有 8 題,題目的難度由出題者(內建題目是事先寫好的,其餘由 AI)判斷,沒有經過大量考生校準。

## 重上一堂課

每堂課的課文、題目與作答都存在資料庫裡。分數不理想時,可以在那堂課的結果頁按「重上這堂課」,用同一份內容再上一次。

- 重上**只當練習**:題目已經看過,第二次一定比較高分,所以分數不計入日曆與月平均。日曆上會在原本那堂課底下註明重上了幾次、各得幾分。
- 不會與不熟的項目照常更新。同一題再錯一次,是累加在同一個項目上。
- 重上不需要 AI 重新備課,不耗產生課程的額度;只有對話與批改會用到。
- 還有課沒上完時不能重上,要先上完或放棄那堂課。
- 重上的課沒有「課前重溫上一課」。

## 課程會不會重覆

會盡量避免,而且由程式檢查,不是只相信 AI:

- **主題**:每個學習階段有 20 個主題,程式挑最久沒上過的。整份清單輪完之前不會重覆;輪完之後主題會再出現,這時程式會把以前同主題的課名告訴 AI,要求寫不同的情境。
- **文法重點**:由程式依清單順序(由淺到深)指定,AI 不能自己挑。每個等級有 6–11 個,輪完一遍才回到第一個。
- **單字**:最近 60 堂課的重點單字會告訴 AI 避開。還在複習中的單字(答錯最多的優先,最多 5 個)會刻意放回新課文裡再接觸一次,但不佔新單字的名額。
- **檢查**:課程產生後,程式把新課文和所有上過的課文比對,算出相似度(兩篇課文中連續三個字的片段有多少比例相同)。同主題但重寫過的課文通常低於 10%;達 50% 就視為幾乎相同,會要求 AI 重新產生一次(那堂課多用 1 次品質類額度,只重試一次)。
- 比對結果記在每堂課裡,結果頁最下方的「重覆檢查」可以看到:比對了幾堂、最像哪一堂、相似度多少、哪些重點單字以前教過。
- 每個等級的第一堂課是內建的起始課(見「備課要等多久」),內容固定,所以沒有重覆檢查的結果。它教過的主題、文法與單字同樣會算進上面的規則;已經備好、還沒上的課也算。

## 回顧與複習

- 「回顧」頁可以看本週、本月或指定月份不會與不熟的內容,並直接練習。
- 每個項目會列出最近一次答錯時你的作答,並在正確答案裡用黃底標出答錯的地方。手動標記「我不熟」的項目沒有作答可列。
- 這項功能加入之前的紀錄,程式啟動時會從當時的上課紀錄把作答補回來。只有「單獨做複習練習」時答錯的舊紀錄當時沒有存,無法補回。
- 複習全部在本機判分,不耗 AI 額度。

### 間隔複習

學過的內容隔一段時間再考,越熟隔越久。

- **每個新單字都會進入複習**,不只是答錯的。剛看完單字表就答對只代表短期記憶,要隔一段時間還答得出來才算記住。這項規則加入之前就答對的舊單字不會補進複習,單字表上也就沒有「現在」的狀態。
- 第一次就答對、之後也沒錯過的新單字:隔 1 → 4 → 16 → 64 天各複習一次。
- 答錯、不熟或手動標記的項目:隔 1 → 2 → 4 → 8 → 16 → 32 → 64 天。答錯就回到 1 天。
- 間隔達 64 天仍然答對,才標為已掌握,不再出現。
- 還沒到期就提前練習而答對的,不會拉長間隔。
- 寫作與對話的錯誤,複習時是訂正題:要把正確的句子打出來,由程式判斷,不是自己評量記不記得。
- 每堂課開頭的暖身複習最多 20 題(20 分鐘的課)或 24 題(25 與 30 分鐘的課),是每堂新單字數的 4 倍;超過的留在「回顧」頁的複習練習。

### 每堂課幾個新單字

每堂課的新重點單字:20 分鐘的課 5 個,25 與 30 分鐘的課 6 個。也就是國小每堂 5 個,國中、高中與大學每堂 6 個(每個等級的第一堂是 20 分鐘份量的起始課,5 個)。這個數字的依據:

- 沒有研究直接給出「一天學幾個最好」。能查到的是:研究者規劃學習量時常用的基準是每年約 1,000 個字族(Nation, 2014);把學過的字鞏固住,比多教新字重要(Schmitt, 2008)。
- 每天 5 個新字,一年約 1,800 個,已經高於上面的基準。再多的話,受限的是複習量:每個新單字之後至少要複習 4 次,每天 5–6 個新字,穩定後每天就有 20–24 題複習。
- 兒童在課堂環境下字彙成長通常比青少年與成人慢(Muñoz;Cameron),所以國小是份量最少的 20 分鐘(5 個新字)。

## 課後影片

每堂課的結果頁會建議一支符合該等級的 YouTube 英文影片,用來補課堂上不夠的聽與讀的量。建議打開英文字幕,邊聽邊讀,看得懂大意就好。

- 影片來自程式內建、事先逐一查證過連結的固定清單,不是 AI 當場給的(AI 會編出不存在的網址)。
- 依等級挑選;國小學生優先給兒童影片。每堂課換一支,整份清單輪完才重複。
- 影片放在 YouTube 上,之後可能被下架。連結失效時,卡片上有同一系列其他影片的連結。
- 清單共 111 支。大約一半的系列由發布者自己標示程度(例如 VOA Learning English、BBC Learning English、British Council);其餘(例如 TED、Kurzgesagt、CrashCourse,以及 C1 與 C2 的區分)是整理清單時的判斷,不保證每一支都剛好符合。
- 整理時逐一確認過連結存在,但沒有把每支影片看過一遍;是否適合闔家觀看,依據的是 YouTube 自己的標記。

## 即時語音對話

課程裡的情境對話用即時語音進行:學生直接說,老師也用聲音回答,不經過「語音轉文字、再由文字模型回覆、再朗讀」。老師聽到的是學生原本的聲音(打字對話裡的麥克風是 Chrome 先把聲音猜成文字,發音不準的字常被自動修正),老師的聲音也比電腦的朗讀語音自然。

- **不用按按鈕**:按「開始對話」後直接說,停下來約 1.2 秒老師就接話。老師先開口,第一句是這堂課寫好的開場白。
- **輪數**和打字對話相同:20 與 25 分鐘的課學生說 5 輪,30 分鐘的課說 6 輪。說滿就自己結束並關掉麥克風;也可以隨時按「結束對話」,之後按「再說一次」會接著進行,只剩沒用完的輪數。
- **紀錄與評分**:每一次來回的文字稿由伺服器記進這堂課的對話紀錄,交卷時照原本的方式批改、計入口說分數,並產生訂正題。只有雜音、沒有聽到說話內容的那一次不算一輪。
- **老師說話時**預設先不收音,避免把喇叭的聲音錄回去;勾選「我戴了耳機」後可以直接打斷老師。這個選擇會記住。
- **改用打字**:沒有麥克風、語音連不上或被額度上限擋下時,會自動改用原本一來一往的打字對話;學生也可以自己按「改用打字對話」。兩種方式共用同一份紀錄與輪數。
- 一場對話最長 5 分鐘;離開頁面就會關掉麥克風與連線。
- 上方的「**即時對話**」頁面是課堂以外的自由練習:同樣的方式,老師挑一個主題聊 5 輪,不計分,也不留紀錄。
- 使用 Gemini 的即時語音模型 `gemini-3.8-live`(可以在 `.env` 用 `AI_MODEL_LIVE` 更換)。2026-11-24 用真實的 key、合成的學生語音實測:學生說完到老師開口 1.1–1.7 秒;故意說錯的句子,老師多數會先把正確的句子說一次再接話。
- **API key 只在本機伺服器使用**:瀏覽器把聲音交給本機伺服器,由伺服器連到 Google,key 不會送到瀏覽器。
- **隱私**:學生的聲音會送到 Google。使用免費額度時,內容可能被用來改進 Google 的產品,也可能由人工審閱。請不要說出真實姓名、地址、學校等個人資料。
- 免費方案可以使用即時語音,但 Google 沒有公布它的數量上限。被上限擋下時會出現通知(見「額度上限與通知」),對話改用打字繼續。麥克風開著的期間連安靜的聲音也在傳,所以想得越久,用的額度越多。

## 聽力音檔

聽力課文和聽寫句子由 Gemini 的語音合成模型事先唸好、存成音檔,上課時直接播放,聲音比 Chrome 的朗讀語音自然。下一堂課前的「重聽上一課」用的是同一份課文音檔。

- **只做這兩種**:單字發音、跟讀示範、老師說的話、分級測驗的聽力,以及暖身複習裡以前的聽寫句子,仍然由 Chrome 朗讀(不耗額度)。所以一堂課裡會聽到兩種聲音。
- **全部在背景做,不會讓學生等**:課一備好就接著做它的音檔;內建的起始課和現場產生的課,在進入課堂時才開始做。順序是正在上的課(課文 → 聽寫句子)→ 每一堂備好的課的課文 → 備好的課的聽寫句子。
- **沒有音檔的那一段由 Chrome 朗讀**:還沒做好、當天額度用完、模型做不出來,或音檔讀不到時都是這樣,學生按了播放一定聽得到。上課中做好的音檔,不用重新整理頁面就會用上(網頁每 15 秒問一次)。
- **語速依課程的等級**:A1–A2 慢而清楚,B1 中等,B2 以上是自然的語速。
- **同樣的內容只做一次**:重上同一課、兩位使用者上同一堂起始課,都共用同一份音檔。
- **只保留還用得到的**:進行中的課、備好的課,以及每位使用者上完的最近一堂的課文;其餘自動刪除(每次製作音檔時,以及程式啟動時)。音檔放在 `data/audio`,刪掉也沒關係,需要時會重做(會再用掉額度)。
- **額度**:一堂課用 3 次:課文 1 次,聽寫句子 2 句各 1 次。2026-11-24 在免費方案看到的上限是每個語音合成模型每分鐘 3 次、每日 10 次;程式用兩個模型(前一個到上限就換後一個),一天合計 20 次,大約是 6 堂課的量。為了不超過每分鐘的上限,同一個模型兩次請求至少隔 21 秒。到上限時會出現通知(見「額度上限與通知」)。
- **設定**:在 `.env` 設 `AI_SPEECH=off` 可以完全不用,全部由 Chrome 朗讀;`AI_MODELS_SPEECH` 可以更換模型。
- 2026-11-24 用真實的 key 實測:
  - A2 的起始課(課文 78 字、聽寫 2 句):三段共 48 秒做完。課文的音檔長 47 秒(每分鐘約 100 字)、2.2 MB;請另一個模型把音檔聽寫回文字,和原文 78 個字完全相同。
  - 比最長的課文再長一點的情況(約 500 字;現在最長的課文是 C2 的 400 字):37 秒做完,音檔長 3 分鐘(每分鐘約 166 字)、8.6 MB,唸到最後一句。聽寫回來的 493 個字裡有 3 個和原文不同,其中 2 個是聽寫那一方的問題(人名、數字的寫法),另 1 個(notice 聽成 noticed)分不出是唸錯還是聽錯。
- **隱私**:送給 Google 的只有課文與聽寫句子的文字,不包含學生的作答或聲音。

## 資料與備份

所有資料存在 `data` 資料夾裡(`english.db`,以及同名加上 `-wal`、`-shm` 的兩個檔案,三個要放在一起),包含使用者、上課紀錄、複習項目與每個人的 API key。

- **備份**:先停止程式,再複製整個 `data` 資料夾。
- **佔用空間**:一堂課連同作答、結果與弱點項目約 40 KB。每天一堂、上一整年約 15 MB。另外,`data/audio` 裡的聽力音檔每堂課約 2–9 MB(等級越高課文越長),但只保留幾堂課的份量,不會越積越多;備份時可以不包含這個資料夾。
- **搬到另一台電腦**:把 `data` 資料夾放到新電腦上專案的同一個位置。
- API key 以明碼存在這個資料夾裡。把資料夾給別人,等於把 key 也給了對方。

## 免費額度與模型

程式把 AI 呼叫分成四類,用不同模型,以節省額度:

| 類別 | 用途 | 每堂次數 | 預設模型 |
|---|---|---|---|
| 品質類 | 產生整堂課、批改對話與寫作 | 2(課文和舊課幾乎相同而重新產生時 3) | `gemini-4-hydrogen` → `gemini-3.8-flash` → `gemini-3.5-flash-lite` |
| 對話類 | 問老師;情境對話改用打字時的每一輪 | 問老師最多 5;打字對話最多 5–6 | `gemini-3.5-flash-lite` |
| 即時語音 | 情境對話(每堂一場),以及「即時對話」頁面的自由對話 | 1 場,學生說 5–6 輪 | `gemini-3.8-live` |
| 語音合成 | 聽力課文與聽寫句子的音檔(在背景事先做好) | 3 | `gemini-3.8-flash-tts` → `gemini-3.8-flash-lite-tts` |

前面的模型額度用完或不可用時,自動改用後面的。全部用完時,畫面會說明並引導去做複習。語音合成的額度用完不影響上課:還沒做好的音檔改由 Chrome 朗讀。

### 額度上限與通知

免費額度以 **Google 專案**為單位計算,同時受三種上限限制;任何一種超過,Google 都會拒絕那次請求(HTTP 429):

| 上限 | 意思 | 什麼時候恢復 |
|---|---|---|
| RPM | 每分鐘的請求數 | 大約一分鐘後 |
| TPM | 每分鐘的 token 數 | 大約一分鐘後 |
| RPD | 每日的請求數 | 太平洋時間午夜,也就是台灣時間下午 3–4 點 |

- **遇到 429 時,畫面右上角會出現通知**,任何頁面都看得到:哪個模型、當時在做什麼(備課、批改、對話、製作聽力音檔…)、是哪一種上限、大約何時恢復。按「知道了」關掉。背景備課遇到的也會通知(網頁每 10 秒向本機伺服器問一次)。
- 通知以 API key 為單位:共用同一把 key 的使用者都看得到;用別把 key 的使用者看不到。
- 遇到 429 的模型,程式會先跳過、改用後面的模型:每分鐘的上限跳過一分鐘(Google 建議等更久時照它的時間),每日的上限跳過到額度重置為止。訊息裡看不出是哪一種時,當成每分鐘的上限。
- 「模型忙線」(503,需求過高)是 Google 那邊的負載問題,和額度無關,不會出現這個通知。

上表是每上一堂課的用量:每開始一堂課,背景就備好下一堂(用掉一堂補一堂,見下方「備課要等多久」)。每開始一次分級測驗,背景會再出一份備用的題目,用掉 1 次品質類額度。

Google 不公布各模型的免費額度,實際數字要到自己的 AI Studio 的額度頁面查看,每個帳號可能不同。「設定」頁會顯示本次額度週期已經呼叫幾次、用了多少 token。

下面是 2026-11-24 在一個免費專案的額度頁面上看到的數字,以及這個程式的用量:

| 模型 | 每分鐘請求數 | 每分鐘 token 數 | 每日請求數 | 這個程式的用量 |
|---|---|---|---|---|
| `gemini-4-hydrogen` | 5 | 25 萬 | 20 | 每堂課 2 次(批改、備下一堂),約夠 10 堂 |
| `gemini-3.8-flash` | 5 | 25 萬 | 20 | 前一個模型不能用時才用,同樣約 10 堂 |
| `gemini-3.5-flash-lite` | 15 | 25 萬 | 500 | 問老師、打字對話,以及最後的備援 |
| `gemini-3.8-live` | 不限 | 6.5 萬 | 不限 | 一場語音對話最高約每分鐘 1,300 token,是上限的 2% |
| `gemini-3.8-flash-tts` | 3 | 1 萬 | 10 | 每堂課 3 次(聽力課文與聽寫句子的音檔),約夠 3 堂 |
| `gemini-3.8-flash-lite-tts` | 3 | 1 萬 | 10 | 前一個模型到上限時才用;兩個合計約夠 6 堂 |

- 每分鐘的 token 數離上限都很遠;會先碰到的是前兩個模型的每日 20 次。
- **被拒絕的請求也算次數**:模型忙線(503)或等到逾時的請求,同樣計入每日請求數。Google 那邊負載高的日子,額度會被失敗的請求消耗掉;程式遇到忙線會先跳過那個模型 5 分鐘,避免一直重試。

要更換模型,把 `.env.example` 複製成 `.env`,修改 `AI_MODELS_QUALITY` 與 `AI_MODELS_CHAT`。

### 備課要等多久

AI 產生一堂課需要時間,實測約 40–80 秒。為了不讓學生等,程式做了兩件事;兩者都沒有課可用時,畫面上是「備課」按鈕。

**課程長度依學習階段固定**:國小 20 分鐘、國中 25 分鐘、高中與大學 30 分鐘,不用選,所以每個等級只需要備一堂。(以前可以自己選 20、30、40 分鐘;那時上過的課仍然可以重上,長度不變。)

**內建的起始課。** 程式裡附了 24 堂寫好的課:6 個等級(A1–C2)× 4 個學習階段各一堂,都是 20 分鐘的份量。使用者在某個「等級 + 學習階段」還沒上過課時,第一堂直接上這一堂,不呼叫 AI、不用等、不耗產生課程的額度。所以切到新的等級(包含依分級測驗的建議切換)之後,第一堂課可以馬上開始。

- 起始課是事先寫好的,不是 AI 當場產生的,每位使用者看到的內容相同。
- 它只用在該等級的第一堂。之後的課由 AI 產生,並會避開起始課的主題、文法重點與單字。
- 國中、高中與大學在每個新等級的第一堂因此是 20 分鐘的份量,第二堂起才是 25 / 30 分鐘。開始上課的畫面會寫明。
- 對話與批改仍然需要 API key,所以沒有設定 key 的使用者一樣不能開課。

**預先備課。** 一堂課開始之後,程式在背景把這個等級的下一堂課準備好並存起來。

- 用掉一堂就補一堂。備好的課存在資料庫裡,關掉程式再開也還在。
- 備好的課是照「等級 + 學習階段」分開存的。切到別的等級再切回來,原本備好的課還在,可以直接用。
- 用不到的備課在程式啟動時清掉:長度和學習階段不符的(以前自己選長度時備的),以及使用者已經改到別的學習階段、替原本階段備的。它們的聽力音檔也一併刪除。上課紀錄不受影響。
- 同一位使用者一次只產生一堂課。

**「備課」按鈕。** 開始上課的畫面依下一堂課的狀況顯示不同的按鈕:

| 狀況 | 畫面 |
|---|---|
| 課已經備好,或有起始課可以上 | 「開始」,按下去馬上上課 |
| 老師正在背景備課 | 進度條;備好之後自動變成「開始」 |
| 還沒備好 | 「備課」:按下去請老師準備,備好之後變成「開始」 |

會出現「備課」的情況:背景備課失敗(例如額度用完、模型忙線;背景會先停下來,下次開課或上完課時再試)、把背景備課關掉(見下方的設定),或剛換到一個上過、但沒有備好的課的等級。按了「備課」如果備不成,畫面會寫出原因,可以稍後再按一次。備課時可以離開這個畫面,老師會繼續備,回來時就備好了。

需要等的時候,畫面會顯示**進度條、百分比與預估剩餘時間**(批改時也是)。AI 是一次回傳整個結果,過程中拿不到真正的進度,所以這些數字是用「過去實際花費的時間」推估的:還沒有紀錄時,備課與出題以 60 秒、批改以 30 秒估計,之後每次實際花的時間都會納入。等得比預估久時,進度條會慢下來但不會顯示 100%,並改為顯示已經等了多久。

**額度。** 預先備課會提前使用額度:每開始一堂課,背景就產生下一堂(每堂課 1 次品質類額度)。不想提前使用的話,可以在 `.env` 調整:

- `AI_PREPARE_NEXT=off`:完全不在背景備課,下一堂課要自己按「備課」才準備;分級測驗也不會在背景出下一份題目,下次測驗時才現場出題。內建的起始課與內建的分級測驗仍然會使用。

#### 時間花在哪裡

2026-11-20 用真實的 key 產生 B2、20 分鐘課程的實測:

| 模型與思考程度 | 時間 | 品質 |
|---|---|---|
| `gemini-4-hydrogen`,模型預設(第一順位) | 40 秒、61 秒,另一次回「需求過高」 | 好,但速度看當下負載 |
| `gemini-3.8-flash`,模型預設(第二順位) | 79 秒 | 好;思考用掉的 token 是輸出的三倍 |
| `gemini-3.8-flash`,思考程度 low | 24 秒、33 秒 | 題目與答案正確,但對指示(例如課文字數)遵循得較不精確 |
| `gemini-3.5-flash-lite` | 8 秒 | 題目會出錯,只當最後備援 |

時間幾乎都花在模型的「思考」上。思考程度維持模型預設(品質優先),等待的問題交給預先備課解決。想改用較快的設定,可以在 `.env` 設 `AI_THINKING_QUALITY=low`。

另外,為了在模型出狀況時不白等:

- 每次呼叫都有逾時(品質類 180 秒、對話類 30 秒),超過就換下一個模型。SDK 預設是沒有逾時的。
- 關掉 SDK 自己的重試。模型忙線時立刻換備援,而不是在同一個模型上重試好幾次。
- 記住剛失敗的模型:超過每日額度的,到下一個額度日之前不再嘗試;超過每分鐘上限的,跳過一分鐘;忙線或逾時的,先跳過 5 分鐘。

「設定」頁的用量表會顯示每個模型平均每次等多久;啟動紀錄裡,每次呼叫也會有一行,例如 `[ai] lesson gemini-4-hydrogen 40.0 秒`。

## 隱私與 Google 條款

- **Gemini API 的條款規定使用者須年滿 18 歲,且不得用在可能被未滿 18 歲者使用的應用程式。** 讓未成年學生使用不符合這項條款,可能的後果是 key 被停用。是否這樣使用,由建立 key 的成年人自行判斷。
- 使用免費額度時,送出的內容會被 Google 用來改進產品,也可能由人工審閱。
- 程式送給 Google 的只有等級、學習階段、課程內容與學生的作答,不包含使用者的名稱。
- 請提醒學生,作答時不要寫出真實姓名、地址、學校、電話等個人資料。
- 語音辨識是 Chrome 的功能,說話的聲音會送到 Google 的語音服務處理。
- 製作聽力音檔時,送給 Google 的是課文與聽寫句子的文字。
- 情境對話與「即時對話」頁面用的是即時語音:學生的聲音會直接送到 Google 的即時語音模型,適用上面免費額度的條款。不想送出聲音的話,情境對話可以按「改用打字對話」。

## 已知限制

- 跟讀的分數代表「能不能被聽懂」,不是精確的發音評分。Chrome 會盡量猜出說的字。數字可能被辨識成阿拉伯數字而拉低正確率。
- 即時語音對話靠「安靜約 1.2 秒」判斷學生說完了沒,停頓太久會被當成說完。沒戴耳機時,老師說話的期間不收音,所以不能打斷老師。
- 即時語音對話時老師的糾正是口頭的(把正確的句子說一次);寫下來的訂正要等課後批改。
- 聽力音檔的免費額度一天約夠 6 堂課(見「聽力音檔」)。超過額度的部分當天由 Chrome 朗讀;沒做完的要等之後上課時(進入課堂、換到下一個步驟)才接著補做,程式不會在額度重置的時間自己補做。
- 聽力音檔沒有逐篇檢查是否逐字照唸,只抽驗過兩篇(見「聽力音檔」的實測)。音檔的語速是製作時決定的,播放時不能調整。
- 課文中只有加了底線的字可以點開看意思,不是每個字都能查。其他的字可以用「問老師」。
- 分級測驗每一級只有 8 題,只能粗略分級;它不會自動更改等級。
- 課前重溫的閱讀速度與重述字數只是讓學生和自己比的數字,不代表理解程度,也不計分。
- 課後影片的連結之後可能失效;清單是固定的,不會自動更新。
- 重覆檢查比對的是課文的字面相似度。情節相似但用字完全不同的兩篇課文,不會被判為重覆。
- 每個學習階段的主題只有 20 個,每天上課的話大約三週輪完一遍。
- 內建的起始課每位使用者都一樣,而且沒有經過 AI 依個人弱點調整。等待時的進度條是推估值,不是實際進度。
- 只支援桌面版 Chrome,手機與平板無法使用。伺服器只接受這台電腦自己的連線。

## 給維護的人

```bash
npm install          # 安裝套件
npm run dev          # 開發模式:改程式會自動重新載入,開啟 http://localhost:5173
npm test             # 執行測試
npm run typecheck    # 型別檢查
npm run build        # 建置網頁
npm start            # 正式模式:開啟 http://localhost:3210
```

### 不耗額度的假資料模式

```bash
AI_PROVIDER=mock npm run dev
```

課程、對話與批改都回傳固定的示範內容,隨便貼一個字串當 API key 即可。貼上 `invalid` 可以模擬 key 無效,貼上 `quota` 可以模擬超過額度上限(429)並看到通知。即時對話在這個模式下回傳固定的句子與一小段提示音。這個模式不製作聽力音檔,聽力全部由 Chrome 朗讀。

### 示範資料

```bash
node scripts/seed.ts 96
```

建立一位「示範學生」,並在上個月放入月平均 96 分的上課紀錄,用來查看日曆與月平均。示範學生可以在網頁上刪除。

### 比較模型的產出

```bash
node scripts/compare-models.ts <使用者編號>
```

用該使用者的 key,讓每個設定的模型各產生 A1 與 B2 的課程,回報是否通過格式驗證與 token 用量,並把課程存到 `data/model-comparison/` 供人工檢查。這會消耗真實的免費額度。

### 程式結構

```
shared/     前後端共用:資料結構、判分、間隔重複、分級測驗的判定(純函式,有測試)
server/     本機伺服器:資料庫、API、給 AI 的提示
  ai/       AI 層:provider.ts 是介面,gemini.ts 與 mock.ts 是兩個實作
  starters/ 內建的 24 堂起始課(每個等級一個檔案);starters.test.ts 檢查內容是否符合課程規則
  placement/ 分級測驗:內建的題目(builtin.ts)與出題、判分、紀錄(service.ts)
  ai/live.ts 即時語音對話的介面與兩個實作(Gemini、假資料);liveSessions.ts 管理進行中的對話
  ai/speech.ts 語音合成的介面與 Gemini 的實作;lessonAudio.ts 在背景製作聽力音檔、決定先後順序與保留哪些
  notices.ts 額度上限(429)的通知
  videoList.ts 課後影片的固定清單
client/     網頁
scripts/    產生 App(make-app.sh)與控制啟動停止(app-control.sh)、示範資料、模型比較
```

### 改接其他 AI 供應商或本機模型

課程程式只呼叫 `server/ai/provider.ts` 定義的介面。新增一個實作檔,在 `server/ai/index.ts` 註冊,再把 `.env` 的 `AI_PROVIDER` 改成它的名稱即可。提示文字在 `server/ai/prompts.ts`,與供應商無關。
